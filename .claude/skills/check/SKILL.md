# /check — 품질 점검

## 1. 한 번에 실행

```bash
npm run check
```

`tsc -b` → `eslint .` → `vitest run` 순서로 돈다. 실패하면 거기서 멈추고 원인을 보고한다.

## 2. 실패 시 대응

| 실패 | 대응 |
|---|---|
| `tsc` | 타입을 느슨하게 풀지 말고 실제 원인을 고친다. `Record<K,V>` 키 누락이 가장 흔하다 |
| `eslint` | `npm run lint:fix`로 자동 수정 후 남은 것만 손본다 |
| `vitest` — 기능 테스트 | 기대값을 고치기 전에 **코드가 틀린 건지 기대값이 틀린 건지** 먼저 판단한다 |
| `vitest` — `distribution.test.ts` | 가중치·임계값 변경의 부작용이다. @.claude/rules/core-rules.md 의 "임계값은 팀 크기에 휘둘린다" 참고 |

## 3. 리포트 확인

테스트가 통과하면 두 파일이 갱신된다. 계산 로직이나 corpus를 고쳤다면 **반드시 읽고 눈으로 확인한다.**

- `report.txt` — 실제 생년월일 200명(19,900쌍)의 점수 분포. 중앙값이 45~60을 벗어나면 가중치를 다시 본다
- `report-team.txt` — 5인 팀 진단 샘플 전문. 문장이 어색하거나 조사가 깨지지 않았는지 본다

리포트에서 확인할 것:

- `{A}` `{B}` 치환자가 남아 있지 않은가
- "지영가", "현우이" 같은 조사 오류가 없는가
- 사람을 평가하는 표현이 섞이지 않았는가 (@.claude/rules/corpus-rules.md)

## 4. 보고

통과하면 테스트 수와 분포 요약(중앙값·범위)을 한 줄로 보고한다.
실패하면 무엇이 왜 깨졌는지와 고친 내용을 보고한다. 테스트를 지우거나 기대값을 임의로 맞추지 않는다.
