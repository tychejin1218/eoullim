# 어울림

팀원들의 사주로 협업 성향과 역할을 살펴보는 사내 도구입니다.
Vite + React 19 + TypeScript.

> 팀 빌딩 아이스브레이킹용입니다. 업무 배정·평가·채용 판단의 근거로 쓰지 마세요.

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm run check      # tsc + eslint + vitest 한 번에
npm test           # 테스트 실행 + report.txt / report-team.txt 갱신
npm run build      # dist/ 로 정적 빌드
```

빌드 결과는 정적 파일이라 사내 어디에 올려도 되고, 파일로 열어도 동작합니다.
서버가 필요 없습니다 — 계산이 전부 브라우저에서 돕니다.

## 구조

```
src/core/          DOM에 의존하지 않는 순수 계산. 테스트 대상.
├── pillars.ts     생년월일시 → 팔자, 팔자 코드 인코딩/디코딩
├── truesolar.ts   진태양시 보정 (경도 · 표준시 이력 · 서머타임)
├── elements.ts    오행 점수, 신강·신약
├── tenGods.ts     십성 판정, 그룹 집계
├── compat.ts      1:1 궁합 점수
├── team.ts        팀 진단 (오행 · 매트릭스 · 역할)
└── korean.ts      조사 처리 (이/가, 은/는)

src/data/
├── tables.ts      천간 · 지지 · 지장간 · 오행 상수
└── corpus.ts      해석 문장 corpus

src/ui/            React 컴포넌트 (계산 로직을 두지 않는다)
test/              Vitest — core/ 와 1:1 대응 + 분포 가드
```

데이터 흐름:

```
BirthInput → buildChart → Chart ─┬→ compatibility  (1:1)

```

## 팔자 코드

팀에 공유하는 단위입니다.

```
지영|庚午辛巳庚辰癸未|BE
```

생년월일이 들어 있지 않습니다. 같은 팔자는 60년 주기로 반복되므로 코드만으로 생년월일을 특정할 수 없습니다.
이 설계 덕분에 생일을 알리고 싶지 않은 팀원도 참여할 수 있습니다.

타입으로도 보장됩니다 — `Chart.birth`(생년월일)는 생년월일로 직접 만든 Chart에만 있고,
`decodeChart()`로 코드에서 복원한 Chart에는 `undefined`입니다.

## 직무 축

직무는 **사용자가 고르는 입력**입니다. 사주로 직무를 추천하지 않습니다.

직무 추천은 두 가지로 실패합니다. 첫째, 팀이 꾸려질 때 직무는 이미 정해져 있어서
"당신은 PM 체질"이라는 정보가 행동으로 이어지지 않습니다.
둘째, 실제 직무와 어긋나면 **직무 적합성 판정**처럼 읽혀 사람 평가가 됩니다.

대신 십성(어떻게 일하는가)과 직무(무엇을 하는가)를 겹쳐 봅니다.
같은 프론트엔드라도 한 명은 `기준을 지키는 쪽`, 한 명은 `굴러가게 만드는 쪽`일 수 있고,
그 차이가 협업에서 실제로 쓰이는 정보입니다.

- `JOB_STYLE` — 6직무 × 5성향 = 30문장 (`'ET'`는 특성을 특정할 수 없어 제외)
- 같은 직무 + 같은 성향이 둘 이상이면 `jobOverlaps`로 짚어줍니다
- 팔자 코드의 직무는 **선택적 꼬리표**라, 직무 없는 옛 코드도 그대로 읽힙니다

```
지영|庚午辛巳庚辰癸未|BE     직무 있음
지영|庚午辛巳庚辰癸未        직무 없음 (기존 형식)
```

## 계산에 관해

만세력은 [`lunar-typescript`](https://github.com/6tail/lunar-typescript)를 씁니다.
직접 구현하지 않는 유일한 부분이고, 이 프로젝트에서 가장 검증이 필요한 부분이라
`test/pillars.test.ts`에 절기·윤달·자시 경계 케이스를 박아뒀습니다.

### 시각은 시:분으로 받는다

흔한 사주 앱은 시각을 12시진 드롭다운(`자시`, `축시`…)으로 받습니다.
그런데 자시는 23:00~01:00에 걸쳐 있고, **23시대와 0시대는 시주가 다릅니다.**

```
1990-05-15 23:40 → 시주 戊子   (야자시 — 다음날 일간 기준)
1990-05-15 00:10 → 시주 丙子   (조자시 — 당일 일간 기준)
```

`자시`를 한 칸으로 묶어 대표값 00:00으로 계산하면 23:30~23:59 출생자가 전부 틀립니다.
그래서 이 프로젝트는 시와 분을 그대로 받습니다.

### 진태양시 보정

사주의 시주는 벽시계가 아니라 태양 위치로 정해집니다. 한국은 둘이 최대 1시간 32분까지 벌어진 시기가 있었습니다.

- 1954~1961: 표준자오선 127.5°E (UTC+8:30)
- 1948~51, 1955~60, 1987~88: 서머타임
- 그 외: 135°E 기준이라 서울 시계가 약 32분 빠름

이 이력을 표로 관리하면 틀리기 쉬워서, **IANA tzdata(`Asia/Seoul`)에서 실제 오프셋을 조회**합니다.
Node와 브라우저 모두 내장하고 있어 별도 의존성이 없습니다.

보정은 시주만이 아니라 **일주까지 바꿀 수 있습니다.**

```
1990-05-16 00:10  보정 없음 → 일주 辛巳
                  보정 적용 → 일주 庚辰   (23:38 로 당겨져 전날이 됨)
```

적용하지 않은 것: 균시차(±16분). 국내 만세력 대부분이 평균태양시까지만 보정하므로 기본값을 맞췄습니다.

### 자시 유파

`sect: 2`(야자시설 — 23시 이후에도 일주는 당일 유지)가 기본입니다.
`sect: 1`(조자시설)은 유파 차이지 버그가 아니라서 입력 화면의 `계산 방식`에서 바꿀 수 있게 열어뒀습니다.

## 점수 설계

```
일간 대 일간   40점   기본 결이 맞는가
일지 대 일지   35점   같이 있을 때 편한가
오행 상호보완  25점   서로의 빈 곳을 채워주는가
──────────────────────
              최저 30점 (바닥)
```

동료끼리 돌려보는 도구라 **낮은 점수가 낙인이 되지 않도록** 설계했습니다.

- 바닥 점수를 30점으로 깔았습니다
- 매트릭스에 붉은색을 쓰지 않습니다 (강조 색 하나의 농도로만 표현)
- 모든 해석 문장은 "사람 평가"가 아니라 "방식 차이 + 실행 가능한 팁"입니다

### 판정 우선순위

한 쌍이 두 관계에 동시에 걸리는 경우가 흔합니다. 협업 도구라 **덜 날 선 쪽**을 택합니다.

| 쌍 | 걸리는 관계 | 채택 |
| --- | --- | --- |
| 巳申 | 육합 · 삼형 | 육합 |
| 丑未 | 충 · 형 | 충 |
| 천간합 5쌍 | 합 · 상극 | 합 |

천간합은 전부 상극 관계 위에 성립하므로, 순서를 정하지 않으면 전부 '극'으로 빠집니다.

### 분포 가드

`test/distribution.test.ts`가 가중치 변경의 안전망입니다.
실제 생년월일 200명(19,900쌍)으로 점수를 뽑아 분포가 무너지지 않는지 검사합니다.

```
최저 30  25% 51  중앙 60  75% 70  최고 100  평균 60.1
보완 점수(25점 만점) 평균 16.2  최대 25
```

가중치나 임계값을 바꾸면 이 테스트가 깨질 수 있습니다. 실제 표본으로 다시 튜닝하세요.

### 팀 진단 임계값

인원이 많을수록 평균이 균등에 수렴하므로, 고정 %로 자르면 작은 팀에서만 경고가 쏟아집니다.
그래서 `team.ts`는 잘라내는 대신 `severity`(0~1)를 항상 주고 `notable` 플래그로 강조 여부만 정합니다.

| 팀 크기 | 결핍 notable | 과잉 notable |
| --- | --- | --- |
| 3인 | 53% | 50% |
| 5인 | 33% | 33% |
| 8인 | 14% | 20% |

큰 팀에서 잘 안 뜨는 건 의도한 동작입니다 — 8명이 모였는데도 한 축이 비었다면 진짜 신호입니다.
